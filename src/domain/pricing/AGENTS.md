- Competitor research lives only in the Admin-only `platform_settings` row `competitor_prices`; the engine only classifies and suggests, and customer prices change solely via an explicit Admin save of manual prices.
- Research files and Airalo public retail checks (Admin-triggered, one public page per country taken sequentially in small batches from the sitemap-verified destination map — unmapped territories are COUNTRY_MATCH_REQUIRED, never guessed — EUR data-only, preview then confirm) upsert by competitor+country+package; failures or absences never delete or null stored prices; a market median needs at least two distinct competitors.
- Airalo rows absent from a successful check are kept with a possibly-removed marker (history intact) and excluded from benchmarks until seen again; multi-island destinations are retrieved for display only and never stored as one country price.
- The cost-change queue monitors from an Admin-approved snapshot cost, else a labelled `monitoringBaseline` inside `pricing_snapshot` (never treated as approval); commercial manual price review lives separately in the Admin-only `platform_settings` row `manual_price_review`, and Lite/Plus never enter normal monitoring.
- Manual eSIM prices (country > global package > automatic rule) are stored in the Admin-only `platform_settings` row `manual_pricing` and written to `service_products.sale_price` with `price_overridden`, so the existing sync never overwrites them and no schema change is needed.
- Pasaport's standard Unlimited product is the supplier's Essential tier: catalogue listings and Admin pricing keep only Essential where it exists for a structure, while Lite/Plus stay stored untouched so a premium tier can be added later.
